# dify-offline-repack（引擎 + CLI）操作与使用指南

> 配套 Web：`dify-offline-web/`（FastAPI）。本文面向手工操作与排障。

## 0. 环境要求
- 打包机需能访问 PyPI（默认 `https://pypi.org/simple`，可 `--index-url` 指定内网镜像）。
- 已安装 `uv`（本机 0.12.9；daemon 镜像内亦为最新 uv）。旧版 uv(<0.6) 不支持 requirements 相对 find-links，请升级。
- python >= 3.10（dev venv：`E:\DIFY_PLUGIN\.venv-dev`，含 PyYAML/tomli/fastapi/uvicorn 等）。

## 1. CLI 用法

```powershell
$PY = 'E:\DIFY_PLUGIN\.venv-dev\Scripts\python.exe'
# 查看插件元数据（无需联网）
& $PY -m dify_offline_repack inspect 插件.difypkg
# 重打包：默认双架构单包；--arch x86_64 / aarch64 可缩窄
& $PY -m dify_offline_repack repack 插件.difypkg -o out --arch x86_64,aarch64 `
    --index-url https://pypi.org/simple --glibc-minor 36
# 静态校验离线包
& $PY -m dify_offline_repack verify out\xxx-offline.difypkg
# 批量：目录内所有 *.difypkg（或文本清单）逐一重打包，失败隔离，输出 out\batch-summary.json
& $PY -m dify_offline_repack batch .\插件目录 -o out --arch x86_64
```

产物：`out/<author>-<name>-<version>-offline.difypkg` + `report-…json`。
退出码：0 成功（离线闭包自检通过）／1 业务失败（缺 wheel 等）／2 参数错／3 环境错。

## 2. Web 用法
```powershell
cd dify-offline-web
& $PY -m uvicorn app:app --host 0.0.0.0 --port 8010
```
- 首页 `http://127.0.0.1:8010/`：拖拽/选择 `.difypkg`、选架构与 PyPI 源、提交。
- 任务队列实时进度；完成后下载离线包、查看 JSON 报告。
- **任务管理**：卡片上对失败/错误任务可“↻ 重试”（按原上传与配置重新打包）、“删除”；顶部“🗑 清除失败任务”一键清理全部失败/错误任务（运行中任务会返回 409，不会被误删）。
- 数据目录默认 `dify-offline-web/data/`（可用 `DIFY_OFFLINE_DATA` 覆盖），并发默认 2（`DIFY_OFFLINE_WORKERS`）。
- REST：`POST /api/jobs`、`GET /api/jobs[/{id}]`、`GET /api/jobs/{id}/download|report`、
  `DELETE /api/jobs/{id}`（删除）、`POST /api/jobs/{id}/retry`（重试）、`POST /api/jobs/clear-failed`（一键清除失败）。

## 3. 处理流程（引擎）
1. 解包 difypkg（校验路径穿越），解析 `manifest.yaml`（author/name/version/runner）。
2. 归一化依赖文件：requirements 与 pyproject 并存时保留 requirements（官方模板二者同步）；仅有 pyproject 时提取 `[project].dependencies` → requirements；并从负载移除 pyproject/uv.lock（daemon 以 requirements 路径安装，离线配置对它最通用）。
3. `uv pip compile --python-version 3.12 --python-platform linux` 精确锁定全部传递依赖。
4. 逐架构从 PEP503 索引页抓取 wheel：按 `cp312` + `manylinux_2_N(17≤N≤glibc)` 标签匹配（支持复合标签），URL `#sha256` 校验后落盘 `wheels/`（纯 `py3-none-any` 只取一次）。
5. 向 `requirements.txt` 首行注入 `--no-index --find-links=./wheels/`（uv/pip 均识别）。
6. 重新打成 zip（与官方 difypkg 同构）；统计压缩/解压尺寸与 sha256。
7. 离线闭包自检：`uv pip compile --no-index --find-links wheels` 能复现锁定 → 才算成功。

## 3a. 签名（安全路径：自签 + 目标端第三方公钥）
算法与 daemon 0.6.10 官方一致（RSA-4096 PKCS1v15/SHA256；zip 注释携带 `{"signature","time"}`；`.verification.dify.json` 最后写入；逐条目内容 sha256 级联 + verification sha + 时间串做摘要）。

```powershell
$PY = 'E:\DIFY_PLUGIN\.venv-dev\Scripts\python.exe'
# 1) 生成组织密钥对（PKCS1 PEM）
& $PY -m dify_offline_repack keygen -o ./org_keys/offline-sign-key
# 2) 重打包得到离线包后，用组织私钥签名
& $PY -m dify_offline_repack sign out\xxx-offline.difypkg -k org.private.pem -o out\xxx-offline.signed.difypkg
# 3) 本地校验（正例应 OK；对篡改包应 INVALID）
& $PY -m dify_offline_repack signverify out\xxx-offline.signed.difypkg -k org.public.pem
# 4) 目标端启用第三方验签：
#    .env:  THIRD_PARTY_SIGNATURE_VERIFICATION_ENABLED=true
#           THIRD_PARTY_SIGNATURE_VERIFICATION_PUBLIC_KEYS=/app/storage/keys/offline-sign-key.public.pem
#    把 org.public.pem 拷入 plugin_daemon 数据卷（默认 ./volumes/plugin_daemon 映射 /app/storage）对应路径，
#    然后 docker compose up -d plugin_daemon。
#    此后 FORCE_VERIFYING_SIGNATURE 可保持默认 true：仅持有您私钥签名的离线包可安装。
```
> 快速路径（非生产推荐）：`.env` 设 `FORCE_VERIFYING_SIGNATURE=false`，未签名离线包即可安装。
> 交叉验证：已与官方 0.6.10 二进制（`dify-plugin-windows-amd64.exe`）双向互验通过，且可直接验证市场现行官方签名包；排障过程见 `docs/03-验证记录.md` V7。

## 4. 目标端（离线 Dify）部署步骤
见根 README 与页面底部。要点：
- `.env`：`FORCE_VERIFYING_SIGNATURE=false`（快速路径）＋放大 `PLUGIN_MAX_PACKAGE_SIZE`/`NGINX_CLIENT_MAX_BODY_SIZE`；
- `docker compose up -d plugin_daemon nginx`；
- Dify → 插件 → 本地文件安装 → 选离线包。

## 5. 常见错误与处置
| 现象 | 处置 |
|---|---|
| `missing wheels … (aarch64: N missing)` | 该依赖无目标架构 wheel；先单架构打包；sdist-only 需预构建（M3） |
| `uv pip compile failed` | 检查 `--index-url` 可达性、requirements 是否有 git/url 依赖（离线不支持） |
| `offline recheck failed` | 包内闭包不完整/版本不一致，产物标记失败，勿安装 |
| 目标端仍报 init environment 失败 | 确认目标 daemon 版本（0.6.10/uv、python 3.12）；更旧版本改用内网镜像方案 |
| 安装提示验签失败 | 已设 `FORCE_VERIFYING_SIGNATURE=false`？安全路径（自签+公钥）见规划 |
