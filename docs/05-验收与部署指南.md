## 2. 三分钟自检（任何有网机器）
```powershell
$PY = '.\.venv-dev\Scripts\python.exe'   # 或引擎所在 python
& $PY -m dify_offline_repack verify out-dual\dify-webscraper-0.0.1-offline.difypkg   # 结构+header+wheels
& $PY -m dify_offline_repack batch .\某目录 -o out --arch x86_64,aarch64            # 批量
& $PY -m dify_offline_repack keygen -o org && & $PY -m dify_offline_repack sign 离线包.difypkg -k org.private.pem -o x.signed.difypkg
& $PY -m dify_offline_repack signverify x.signed.difypkg -k org.public.pem          # 应 signature OK
```

## 3. 端到端验收

### 3.1 容器级离线校验（复刻 daemon 环境初始化，无需整套 Dify）
1. 解包离线包：`python -m zipfile -e xxx-offline.difypkg .\plugin-offline`
2. 拉取目标镜像（或目标端同 tag）：
   `docker pull langgenius/dify-plugin-daemon:0.6.10-local`（无 Docker Hub 时用加速源如 `docker.m.daocloud.io/langgenius/...`）
3. 执行 `e2e\container-offline-check.ps1 -Pkg .\xxx-offline.difypkg -Modules dify_plugin,bs4`（内部 `--network none`：uv venv→`--no-index --find-links`→import）
4. 通过判据：输出 `IMPORT-OK <module>` 与 `CONTAINER-OFFLINE PASS`。

### 3.2 真实 Dify 栈安装（目标内网机/有网整栈环境）
1. 拷贝离线包进内网。
2. 目标 Dify `.env`（二选一并放行尺寸）：
   - 安全路径：`THIRD_PARTY_SIGNATURE_VERIFICATION_ENABLED=true` + `THIRD_PARTY_SIGNATURE_VERIFICATION_PUBLIC_KEYS=/app/storage/keys/<org>.public.pem`（把公钥拷入 `./volumes/plugin_daemon/keys/`），保持 `FORCE_VERIFYING_SIGNATURE=true`，安装**已签名**离线包；
   - 快速路径：`FORCE_VERIFYING_SIGNATURE=false`；
   - 恒配：`PLUGIN_MAX_PACKAGE_SIZE=524288000`、`NGINX_CLIENT_MAX_BODY_SIZE=500M`。
3. `docker compose up -d plugin_daemon nginx`
4. Dify → 插件 → 本地文件安装 → 上传 → 期望：环境初始化成功、插件出现在“已安装”，工具/模型可被工作流调用。

### 3.3 Web 验收
- 启动：`.\start-web.ps1` → 打开 `http://127.0.0.1:8010`；拖入官方 `.difypkg` → 选架构/自签 → 任务完成 → 下载离线包（下载 sha 与任务报告一致）。
- 容器版：`docker build -f dify-offline-web\Dockerfile -t dify-offline-repack-web .`（Docker Hub 不可达时加 `--build-arg BASE=docker.m.daocloud.io/library/python:3.12-slim`）→ `docker run -p 8010:8010 -v dify-offline-data:/app/data dify-offline-repack-web`。

## 5. 已知限制
- 目标端安装需 Dify daemon 0.6.x（uv/python3.12）语义；更旧 daemon 见 `docs/02` 兼容矩阵（内网镜像替代方案）。
- sdist-only 依赖：机制已验证（V12），引擎“自动带 sdist+后端闭包”为 P2；当前明确失败。
- 真 Dify 整栈 daemon HTTP 安装编排需整栈环境（api/db/redis）——提供上述 3.2 步骤供真机执行。
